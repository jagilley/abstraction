  `exist`  pairs of SURVIVING learner classes whose representatives share a token
           class — the merges that are structurally available at that proposal.
  `scored` how many of those the probe actually scored (both sides in the probed
           set, both repairing something). `<=tol` / `>tol` split them by loss.
  `ex(tok)` counts pairs sharing a TOKEN class; `ex(dmd)` pairs sharing a DEMAND
  cell, which is the coarser set the probe can actually resolve as one and the set
  a loss of 0 corresponds to. `scored`/`<=tol`/`>tol` are over `ex(dmd)`;
  `all<=tol` is every scored pair within tol, whatever its type.
  `ex(dmd) > 0` with `scored == 0` is (b): the use filter never showed the pair to
  the probe. `ex(dmd) == 0` is (a). `scored > 0` with `<=tol == 0` is (c).

  AN OPEN-INVENTORY ARM IS APPROXIMATE HERE, AND NOT A LITTLE. This rebuild
  assumes the operative book of an adopted level IS the book its commit froze
  -- which is exactly what open_inventory abolishes: there the commit freezes
  the KEY and the book is the live build, moving every cycle. So for an open
  arm the rows/cls/probed/scored columns reconstruct a book the arm did not
  run, and every row is flagged [MISMATCH]. The committed-book coverage lines
  above each table are exact in all cases. The arm is printed rather than
  skipped so its structural columns (token classes, demand cells) are on the
  record.
