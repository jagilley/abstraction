## What to build

Fork `soundboard.py` as the lineage does (every addition `# [sostenuto]`-marked, every knob default off, G-F bit-identical with knobs off). One new op, the **admission set**: under open inventory, `operative(ell)` serves only rows of the live build whose flat key has been admitted. Admission is decided by a walk in the shape of pp4/pp5's: at a cadence, for each level with keys at support, offer the not-yet-decided at-support keys in the loop's own count order (`extend_candidates` already produces exactly that list), up to a cap per pass; for each, fire base ∪ {candidate} as a macro at the era's node on a fresh gate pool of the era's cell, and admit iff the gate says so. The gate is the one knob, three values: `world` (the world's error on the gate pool does not rise, pp4's rule), `read` (the projection's mean level over the same fired configurations does not fall, pp5's strict pooled form, which beat its margin form at both budgets), `none` (admit everything offered, the walk's own floor). The world's error and the DP's winning entry are recorded on every trial whatever the gate decides, so the per-candidate confusion against the world gate exists in the loop as it did in pp5; only the `world` arm is billed for those auditions. The loop's own numbers are the defaults: cadence `recert_every` 5, cap `extend_cap` 8, pool `n_aud` 192, tolerance 0.0.

Two design choices are yours; say what you chose and why in DESIGN before paying. First, whether a rejected key is re-offered on a later pass or decided once: the offline walk decides once, the census op re-offers, and with a stable count order re-offering spends the cap on the same rejects. Second, the base at adoption: gating from the empty base at every level from the moment keys exist (pp4/pp5's setting (b), the version where the gate touches every row, and the one I lean to), against seeding the admission set with the commit-time build and gating only the growth (the census op's shape). If you gate from the empty base, keep `operative()`'s servability fallback and count how often it fires. The era schedule stays yoked to the anchor either way; this round tests the gate's seat at a fixed schedule, not the schedule.

Three arms, seed 0 first: `world`, `read`, `none`, all otherwise `sb_sv_yk`'s configuration (verdict-shaped, infill on, the projection in the grader's seat, yoked to `vo_s3:voi3_dp`), one container each through the lineage's `sweep`. The round-1 brief above is background.

The short version. Round 1 put three gates in the admission set's seat: the world's error on the fired gate pool, the shaped projection's solve level on the same fired states, and none. Both real gates price a candidate by the present cell, and both prune next-level coverage: the world's L2 refusals block seven of the ungated arm's L3 keys on each seed, the read's L3 refusals block three of nine and eight of twenty-two L4 keys. That is the practice arc's demand-blindness finding in this seat. It is also the wrong currency for the value system by the roadmap's own claim: the within-level verdict is the producer's business, and the crossing's value is denominated one level up. The gate should read the next level.

## What to build

Two gate values on the existing op, everything else as round 1 (cadence, cap, pool, count order, decided once, empty base, the yoke, the arm otherwise `sb_sv_yk`).

- **`yield`**, the value read in the next level's currency. Fire base ∪ {candidate} exactly as round 1 does, and on the fired configurations compute the next-level yield share that `sb_yield_label` already defines: the fraction of the configuration's level-(l+1) spans whose key is at support in the learner's own level-(l+1) miner, from the reader's parse. Weight it by the shaped projection's solve level on the same configuration, which is the endogenous stand-in for the label's "zero on an unsolved piece", so the object is next-level share times current-level level. Admit iff its pooled mean does not fall. Nothing here reads the oracle. Note this gate can act at L2 before the readout's first fit, since the share needs no readout and the weight is then a constant; say in DESIGN what you do there.
- **`demand`**, the free comparator with no fire. Admit a level-l key iff the level-(l+1) miner's counts over keys that have the candidate's level-l class as a half sum to at least a threshold (default 1; a knob). This is the learner's own next-level minability read straight off the miner, the roadmap's "raises next-level minability" applied to a candidate entry without the projection. If it alone closes the coverage pruning, the projection is not what this op needs. Log the demand distribution over offered keys so the threshold can be read a posteriori.

Carry one more knob for both and for round 1's `read`: an admission margin `adm_delta` (admit iff the difference is at least minus delta, default 0, pp5's lenient form), not run as an arm this round, and log every trial's difference so the selectivity dial can be set from the record later.

Arms, seed 0 first: `st_gy_yk` (yield) and `st_gd_yk` (demand), one container each through `sweep`, yoked to `vo_s3:voi3_dp`. Round 1's three seed-0 arms and the banked no-walk reference are the comparators and are not re-run. Seed 2 under the SPEC's condition as before.

Gates, each shown to fail before it is reported: G-F unchanged; the round-1 A-gates on the new arms; the yield share on one exported pass equals `sb_yield_label` on the same parse and miner (with the solve weight a constant); the demand count on one exported pass equals a hand count over the miner's keys; a constant share admits everything; and A-1c's re-walk on every pass with a separating pass found. Reuse `reduce_sostenuto.py` and `mk_seedtable.py` unchanged in shape, adding the two arms as columns, so [I] and (a) carry the comparison the round turns on.

There is no resumable checkpoint in this loop (`checkpoint_every` writes the results log only), and an arm costs about 2.3 GPU-hours whether or not the gate is on, so do not build a resume system for this; if you find a cheap honest way to shorten the test, say so and take it.
